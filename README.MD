# kamidere

Multi-tenant SaaS-платформа для онлайн-записи. Один деплой — много бизнесов.
Чистый HTML + Tailwind (CDN) + Vanilla JS, Supabase (БД, Realtime, Storage),
хостинг — Vercel через GitHub.

## Стек

- HTML5 + Vanilla JS (без сборки, без npm)
- Tailwind через CDN (опционально)
- Supabase JS SDK 2.45.x (UMD, CDN)
- Supabase: Postgres + Realtime + Storage
- Vercel: статический хостинг из GitHub

## Установка страницы записи

- Клиентская страница проекта открывается по адресу `booking.html?b=<id проекта>`.
- После загрузки проекта страница создаёт отдельный PWA-манифест с названием бизнеса,
  ссылкой именно на его букинг и иконками 192×192 и 512×512.
- Иконки создаются из логотипа, загруженного во вкладке «Оформление» панели владельца.
  Если логотип не задан, используется фирменная иконка kamidere.
- Кнопка «На экран» вызывает системное предложение установки, если браузер его
  поддерживает; в остальных браузерах показывает шаги добавления ярлыка вручную.
- Для установки необходим HTTPS. На Vercel service worker `service-worker.js`
  публикуется в корне сайта; браузеры на iPhone/iPad используют системное меню
  «Поделиться» → «На экран Домой».

## Телефон и шаблоны проектов

- В публичной форме записи код `+7` подставляется автоматически; маска принимает
  10 цифр российского номера после кода страны, начиная с `8` или `9`, и сохраняет
  полный номер в заявке. Такие же префикс и проверка длины используются в полях
  телефона настроек проекта.
- Декоративный тессеракт на странице записи строится в SVG, вращается и управляется
  перетаскиванием; системная настройка уменьшения движения отключает автоповорот.
- При создании проекта суперадминистратор может выбрать готовый шаблон направления
  бизнеса. Шаблон заполняет типовой список услуг; услуги можно изменить и дополнить
  перед сохранением. В шаблоне цены оставлены пустыми, чтобы бизнес указал свои.
- Выбранное направление сохраняется в проекте и меняет заголовок и описание
  публичной страницы. Для автомобильных направлений форма запрашивает марку/модель
  и госномер и передаёт их в поле `car_info`.
- Если security-миграция уже применена, выполните отдельно
  [`supabase-industry.sql`](./supabase-industry.sql) в SQL Editor. Это добавляет
  колонку `industry` и включает её в публичное представление, не удаляя данные
  или сессии; полный security-скрипт повторно запускать не нужно.
- После security-миграции примените
  [`supabase-booking-validation.sql`](./supabase-booking-validation.sql): он
  добавляет honeypot и серверную проверку длины имени/комментария, российского
  телефона и даты заявки. Это базовая антиспам-защита, не лимит запросов по IP.
- Затем примените [`supabase-booking-schedule.sql`](./supabase-booking-schedule.sql):
  публичная страница показывает свободные старты с шагом 30 минут на сегодня и
  следующие 30 дней, с учётом рабочих дней, часов и длительности услуги. RPC
  возвращает только время, без данных клиентов. Сервер повторно проверяет заявки
  и не позволяет двум клиентам занять пересекающиеся интервалы; длительность
  сохраняется в заявке, поэтому последующее изменение услуги не меняет занятое
  время. Статус «Отменена» и удаление заявки освобождают интервал; повторное
  включение отменённой заявки проверяется на пересечение.

## Supabase: закрытие административного доступа

- Разверните изменения фронтенда одновременно с применением
  [`supabase-security.sql`](./supabase-security.sql) через SQL Editor проекта Supabase.
  Скрипт переводит выдачу административных
  сессий на сервер, включает RLS для проектов, услуг и заявок и закрывает прямой
  вызов административных RPC. Все ранее созданные сессии будут отозваны — после
  применения нужно войти заново.
- Если `supabase-security.sql` уже был применён и создание проекта завершается
  ошибкой `function gen_salt(unknown) does not exist`, выполните
  [`supabase-password-crypto-search-path.sql`](./supabase-password-crypto-search-path.sql)
  в SQL Editor. Миграция добавляет схему установленного `pgcrypto` в
  `search_path` функций создания проекта и обновления пароля; повторно запускать
  полный security-скрипт или сбрасывать данные не нужно.
- Панель владельца обновляет список заявок раз в 15 секунд вместо подписки
  Realtime: анонимная Realtime-подписка не используется для доступа к личным
  данным клиентов.
- Проверьте успешное выполнение скрипта и сценарии входа/создания проекта в
  Supabase перед выкладкой: локальная среда не содержит вашей схемы и настроек
  Supabase.
